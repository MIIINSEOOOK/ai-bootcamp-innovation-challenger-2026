# 데모 페르소나 (자립준비청년 안전망 감지 AI 에이전트)

기능명세서 F3 "청년별 시나리오(정상 유지형/점진적 악화형/급격한 단절형 등) 샘플 데이터를 미리 구성해 시연"을 위한 **완전히 가상인** 인물 12명 + 60일치 안부 응답 로그 데이터셋. 실제 청년 개인정보는 전혀 사용하지 않았다 (FAQ Q4 "MVP는 실제 개인정보를 일절 사용하지 않고 가상의 데이터만 구현한다"에 대응).

## 디렉토리 구조

```text
data/personas/
├─ README.md              # 이 파일
├─ schema.json             # 페르소나 레코드 JSON Schema
└─ personas.json           # 12명 + 60일 로그 전체 데이터 (정적 데이터, 아래 "생성 방법" 참고)
```

## 데이터 구조

각 레코드(자세한 필드는 `schema.json` 참고):

- `independence_status`: 보호종료일/주거형태/취업·학업상태 (F3의 "기본 자립상태 정보")
- `backstory`: 1~3문장 배경 서사. 진단·낙인적 표현을 피하고 상황 설명 중심으로 작성 (FAQ Q1 "AI는 진단하지 않는다"는 원칙에 맞춤)
- `daily_logs`: 60일치 {발송여부, 메시지, 응답여부, 응답까지 걸린 시간(분), 응답유형(좋음/보통/힘듦), 응답 텍스트} — F1/F2 원천 데이터
- `derived_summary`: 응답률(전체/최근7일/직전7일)·변화량·최대/현재 연속 미응답일수 — F3이 계산할 집계값의 스냅샷
- `expected_ai_label` / `expected_rationale_example` / `case_history`: **항상 비어있음(null / null / [])**. F4(AI 분석 라벨·근거)와 F7(전담요원 처리 이력)은 이 페르소나가 제공하는 원천 데이터(F1~F3)를 입력받아 실제 서비스 로직/사람이 만들어내는 산출물이지, 페르소나 단계에서 미리 채워둘 데이터가 아니다. 필드만 남겨둬서 F4/F7을 구현할 때 어디에 값을 채워야 하는지 스키마로 보여주는 용도.

## 생성 방법

`personas.json`은 고정 시드(`random.Random(seed)`, 페르소나별 1~12)와 고정 기간(2026-09-13 기준 최근 60일)으로 결정론적으로 생성한 정적 데이터다. 정상 유지/점진적 악화(완만·중간·심함)/급격한 단절(완전 무응답 포함) 3가지 로그 패턴에 파라미터(severity/cutoff_day/post_cutoff_prob)를 다르게 줘서 12명의 변형을 만들었다. 생성 스크립트는 재실행해도 완전히 동일한 결과만 나오는 것을 확인한 뒤 저장소에서 제거했고(재현성보다 간결함을 택함), 이 파일이 유일한 소스다.

데이터를 다시 만들거나 변형을 추가하려면 이 문서의 로직 설명을 참고해 새로 스크립트를 작성하면 된다.

## 한계 / 주의사항

- 응답 텍스트는 몇 가지 짧은 예시 문구 풀에서 뽑은 것으로, 실제 청년의 표현을 흉내낸 것이 아니다. UI 시연용 placeholder로만 사용할 것.
- `expected_ai_label`/`expected_rationale_example`/`case_history`는 항상 비어있다. F4/F7을 구현하면 이 페르소나의 `daily_logs`/`derived_summary`를 입력으로 돌려 채워야 한다.
- 이름/나이/직업 등은 전부 가상 조합이며 특정 실존 인물을 지칭하지 않는다.
