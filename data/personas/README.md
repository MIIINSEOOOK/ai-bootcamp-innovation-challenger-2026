# 데모 페르소나 (자립준비청년 안전망 감지 AI 에이전트)

기능명세서 F3 "청년별 시나리오(정상 유지형/점진적 악화형/급격한 단절형 등) 샘플 데이터를 미리 구성해 시연"을 위한 **완전히 가상인** 인물 12명 + 60일치 안부 응답 로그 데이터셋. 실제 청년 개인정보는 전혀 사용하지 않았다 (FAQ Q4 "MVP는 실제 개인정보를 일절 사용하지 않고 가상의 데이터만 구현한다"에 대응).

## 디렉토리 구조

```text
data/personas/
├─ README.md              # 이 파일
├─ schema.json             # 페르소나 레코드 JSON Schema
├─ generate_personas.py    # 생성 스크립트 (고정 시드, 재실행해도 동일 결과)
└─ personas.json           # 생성된 12명 + 60일 로그 전체 데이터
```

## 데이터 구조

각 레코드(자세한 필드는 `schema.json` 참고):

- `independence_status`: 보호종료일/주거형태/취업·학업상태 (F3의 "기본 자립상태 정보")
- `backstory`: 1~3문장 배경 서사. 진단·낙인적 표현을 피하고 상황 설명 중심으로 작성 (FAQ Q1 "AI는 진단하지 않는다"는 원칙에 맞춤)
- `daily_logs`: 60일치 {발송여부, 메시지, 응답여부, 응답까지 걸린 시간(분), 응답유형(좋음/보통/힘듦), 응답 텍스트} — F1/F2 원천 데이터
- `derived_summary`: 응답률(전체/최근7일/직전7일)·변화량·최대/현재 연속 미응답일수 — F3이 계산할 집계값의 스냅샷
- `expected_ai_label` / `expected_rationale_example`: F4가 내려야 할 판정과 근거 텍스트의 **기대값(ground truth)**. `generate_personas.py`의 규칙 기반 `classify_status()`로 계산했으며, 실제 F4 AI 구현을 대체하는 것이 아니라 데모·테스트 시 "AI가 이 페르소나를 보고 어떤 판정을 내려야 하는가"를 검증하기 위한 참고치다.

## 생성 방법

- `generate_personas.py`가 `random.Random(seed)`로 페르소나별 고정 시드를 써서 재실행해도 항상 동일한 `personas.json`을 만든다.
- 기간은 2026-09-13 기준 최근 60일 고정.
- 3가지 로그 생성 패턴(`build_logs_stable`/`build_logs_gradual_decline`/`build_logs_abrupt`)에 `severity`/`cutoff_day`/`post_cutoff_prob` 같은 파라미터를 다르게 줘서 서브타입 변형을 만든다.

재생성:

```bash
cd data/personas
python generate_personas.py
```

## 한계 / 주의사항

- 응답 텍스트는 몇 가지 짧은 예시 문구 풀에서 뽑은 것으로, 실제 청년의 표현을 흉내낸 것이 아니다. UI 시연용 placeholder로만 사용할 것.
- `expected_ai_label`은 단순 임계값 규칙(연속 미응답일수/최근 7일 응답률/변화량)으로만 산출한 것이라, 실제 F4를 구현할 때 그대로 채택하기보다 출발점 정도로만 참고할 것.
- 이름/나이/직업 등은 전부 가상 조합이며 특정 실존 인물을 지칭하지 않는다.
